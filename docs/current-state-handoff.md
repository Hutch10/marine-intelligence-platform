# Marine Project Current-State Handoff

Last updated: March 13, 2026

This document reflects the actual current repository state in `C:\Users\hetfw\marine` at the time of writing. It is intended as a developer handoff for the implemented frontend, backend stubs, shared UI, typed web data layer, database foundation, worker skeletons, and current verification status.

## 1. Repo Structure Overview

The repo is currently organized as a small monorepo with two active app workspaces:

- `apps/web`
  - Next.js App Router frontend
  - Shared layout and UI primitives
  - Typed mock data layer under `lib/api`
- `apps/api`
  - Lightweight typed backend stub layer
  - Mock route definitions
  - Database schema/bootstrap foundation under `src/db`
  - Worker/job skeletons under `src/workers`

There is no real database integration, queue system, or external AI integration wired yet.

## 4. Web Data Layer Summary

The typed web data layer lives under:

- `apps/web/lib/api/types.ts`
- `apps/web/lib/api/mock-data.ts`
- `apps/web/lib/api/client.ts`

### Types

`types.ts` currently defines typed view models for:

- dashboard metrics, missions, activity, quick access
- investigations filters, signals, tracks, hypotheses, evidence
- data explorer actions, datasets, preview series, metadata, summary signals
- ocean map layers, map stats, region metrics, timeline steps
- AI Lab prompt context, suggested prompts, result sections, source references

### Mock data

`mock-data.ts` contains current typed mock data for:

- dashboard overview
- investigations workspace
- data explorer workspace
- ocean map workspace
- AI Lab workspace

### API client

`client.ts` is a lightweight shared data access layer used by the frontend.

Current behavior:

- tries to resolve data through the local typed backend route stub
- falls back to local mock data if needed

Currently wired client domains:

- `dashboard.getOverview()`
- `investigations.getWorkspace()`
- `dataExplorer.getWorkspace()`
- `oceanMap.getWorkspace()`
- `aiLab.getWorkspace()`

This is intentionally simple and does not yet use:

- fetch-based API routes
- React query/state libraries
- caching
- retry policies

## 8. AI Endpoint Summary

The structured mock AI endpoint is:

- `POST /ai/analyze`
  - `apps/api/src/routes/ai.ts`

### Implemented now

The endpoint currently:

- accepts:
  - `prompt: string`
  - `context?: string[]`
- returns a typed structured response containing:
  - `prompt`
  - `summary`
  - `findings`
  - `evidence`
  - `confidence`
  - `uncertainty`
  - `suggestedNextActions`
  - `sources`

The route behavior is still mock-based, but more structured than a simple pass-through stub:

- it maps result sections by title instead of relying only on array position
- it uses AI Lab workspace mock data as the source of truth
- it lightly adapts output text based on incoming prompt/context

### Current response shape

```ts
interface AnalyzeResponse {
  prompt: string;
  summary: AnalyzeResponseSection;
  findings: AnalyzeResponseSection;
  evidence: AnalyzeResponseSection;
  confidence: AnalyzeResponseSection;
  uncertainty: AnalyzeResponseSection;
  suggestedNextActions: AnalyzeResponseSection;
  sources: AiLabSourceReference[];
}
```

### Intentionally stubbed

Not implemented yet:

- OpenAI or any external model call
- queue/background processing
- persistence to `ai_analyses`
- streaming responses
- evaluation/guardrails logic
